# Saved leasing enquiries and GA4 reconciliation

Implemented 18 October 2026. Read this alongside the dated audit in SEO_LEAD_MEASUREMENT_20261016.md; that audit describes the earlier state.

## What each event means

| Signal | Meaning | Count as a qualified leasing lead? |
|---|---|---|
| phone_click / email_click / whatsapp_click, existing GTM tel_click / mailto_click | A contact link interaction | No |
| Enhanced-measurement form_start / form_submit | A browser interaction; not proof of database persistence | No |
| generate_lead + lead_type=leasing + lead_stage=submitted + form_name=contact_enquiry | Midpoint returned ok and an opaque saved enquiry ID for a supported leasing interest | No |
| generate_lead + lead_type=accommodation + form_name=suites_booking_request | A saved accommodation request | No; exclude from leasing submissions |
| qualify_lead | Separate human-confirmed CRM qualification | Only after the agreed human qualification process; never infer from a submission or assignment |
| close_convert_lead | Separate confirmed commercial outcome | Separate from both submission and qualification |

No qualification event or CRM stage change is generated by this release. Existing key-event definitions, default values and Ads goals are unchanged. The GA4 total of all key events still includes contact-click events and must not be labelled qualified leads.

## One join key, separate delivery states

The opaque `lead_id` in the leasing event is exactly Midpoint `Enquiry.id` and the CRM intake's `externalId`. The browser event also carries `event_id` with that ID for inspection. GA4's general event API does not guarantee deduplication of arbitrary events by that parameter; this implementation suppresses repeat calls for the same saved ID within the running page/application instance.

`crm_delivery_status=accepted` requires a successful CRM response containing a saved CRM record ID. `unconfirmed` means that a CRM receipt was not established. Either state is still a saved Midpoint submission. Neither proves an email/inbox receipt, a response by a person, or qualification. An unavailable CRM or analytics tag must not cause a successfully saved form to display a failure and encourage another submission.

The CRM payload now includes its supported `utm.source`, `utm.medium` and `utm.campaign` fields from the saved last-touch attribution. Existing first/last-touch notes remain present. The live CRM's compiled intake schema was checked before using this contract; no CRM repository/schema change is required. Historical CRM records are not re-posted or relabelled.

## GA4 reporting setup

The Midpoint stream is `G-9XLN2SH5ER` in property `532738245`. Five event-scoped custom dimensions were created and independently read back on 18 October:

| Display name | Parameter |
|---|---|
| Saved enquiry ID | lead_id |
| Enquiry type | lead_type |
| Enquiry stage | lead_stage |
| CRM receipt status | crm_delivery_status |
| Enquiry form | form_name |

For saved leasing submissions, filter event name `generate_lead`, Enquiry type `leasing`, Enquiry stage `submitted`, and Enquiry form `contact_enquiry`. Break down by Saved enquiry ID and CRM receipt status. Match each ID privately to the CRM external ID. Use an event-count or distinct-ID readout with explicit filters, not the all-key-event total. Exclude known QA IDs such as `qa_transport_only_20261018` and all test/spam records from commercial reporting. The ID dimension is deliberately for low-volume reconciliation; unique IDs can create high cardinality, so use raw export/system reconciliation if volume materially increases.

Custom definitions apply to new data after registration; they do not recover historical event parameters into old reports. Keep qualification and converted-lead reports filtered by their separate event names and the authoritative human CRM outcomes. There is no accepted qualified organic-enquiry baseline yet.

## Delivery and privacy boundaries

The server renders the configured public GA4 destination on the page. Application events explicitly target that destination. Before `gtag` initializes, the adapter queues Google's standard arguments-shaped event command instead of a plain GTM custom-event object. That removes dependence on a separately configured GTM trigger for the fallback path. It emits one application command, not parallel GA4 and GTM copies. Existing GTM-only surfaces retain their contract; staging/explicitly disabled GA4 destinations do not emit application analytics.

Leasing events contain an opaque enquiry ID, allowlisted interest, stage/type/form, receipt status and limited source labels. They exclude names, email/phone, free-text message, arbitrary vacancy-query values and URL query strings. Email-like attribution labels are omitted. Existing consent settings and blockers remain respected; no server-side tracking bypass or Measurement Protocol credential was added. Browser blocking, consent, network loss and reporting delays can still make GA4 smaller than the database/CRM source of truth. A queued command or attempted request is not a Google ingestion receipt.

## Validation and remaining live gate

Automated tests cover delayed tag initialization, explicit destination, repeat saved-ID suppression, unsupported/unsaved requests, disabled destinations, tag exceptions, CRM receipt validation, structured attribution and persistence/captcha failure boundaries. The full suite passed 184 tests across 42 files with isolated PostgreSQL integration; production build/type checks passed. An isolated browser harness compiled from the actual analytics module produced the expected GA4 transport request, preserving the saved key and submission labels. Collection endpoints were blocked in the acceptance test. No database or CRM request was made by that harness. These checks do not establish a real CRM-to-GA4 ingestion match.

A final real end-to-end submission requires a designated test contact and explicit approval for the existing CRM/leasing notifications it can trigger. Verify CAPTCHA, saved ID, the matching CRM external ID and structured source, one GA4 capture event in DebugView/realtime, and the applicable notification/readback. Clearly label and exclude that test from commercial totals; do not mark it qualified. No fake qualification or historic conversion backfill is permitted.

The 2 Kingfisher area conflict and numeric-estimate exclusion remain unchanged. Source approval is still required before correcting either area or rent.
